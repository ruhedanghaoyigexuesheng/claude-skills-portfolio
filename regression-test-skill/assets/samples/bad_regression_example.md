# 错误示范：只测支付成功/失败（A8）

> 开课对比用：展示「普通回归」与「工作流回归」的差距。

## 本次改动

```text
优化支付回调逻辑，修复支付成功后订单状态偶发未更新的问题。
```

## ❌ 普通回归（不合格）

测试同学第一反应往往只写：

| 测什么 |
|--------|
| 支付成功 |
| 支付失败 |

### 问题

- 未覆盖 **订单状态同步**（本次修复点）
- 未覆盖 **支付回调幂等**（重复扣款历史坑）
- 未覆盖 **库存、优惠券、MQ、退款、支付流水**
- 无风险等级，无法排期
- 无历史 Bug 关联，容易重复踩坑

## ✅ 工作流回归（合格方向）

应通过 7 步工作流产出 ≥8 行清单，含：

- 触发原因（支付回调改动）
- 关联 BUG-101～107
- P0：回调幂等、订单状态、支付流水
- P1：库存、优惠券、MQ、退款
- 测试建议（查哪些表/日志/接口）

## 对比结论

| 维度 | 普通回归 | 工作流回归 |
|------|----------|------------|
| 范围 | 2 项 | 8+ 项 |
| 依据 | 直觉 | 改动 + 链路 + 历史 Bug |
| 优先级 | 无 | P0/P1/P2/P3 |
| 可执行性 | 低 | 高（含场景与测试建议） |
