# P0～P3 风险定义

与团队对齐后写入本文件；步骤 5 风险分级以此为准。

## 等级定义

| 等级 | 定义 | 典型特征 | 执行要求 |
|------|------|----------|----------|
| **P0** | 阻断上线 | 资金/订单/库存/权限核心链路；有线上事故史；数据不一致可导致资损 | **必须执行**，不通过不可发布 |
| **P1** | 高风险 | 核心链路次要分支；高并发/MQ 异步；历史 P0 同类问题 | **重点执行**，需明确结论或风险接受 |
| **P2** | 中风险 | 非核心功能；边界条件；兼容与配置类 | 资源允许时执行 |
| **P3** | 低风险 | 文案/样式；非关键路径展示 | 时间允许再测 |

## 判定维度

1. **是否影响**：资金 / 订单 / 库存 / 权限
2. **是否核心链路** / **是否有线上事故史**
3. **是否高并发** / **异步 MQ** / **分布式一致性**

## 执行优先级映射

| 风险 | 执行优先级 |
|------|------------|
| P0 | 必须 |
| P1 | 重点 |
| P2 | 可选 |
| P3 | 可选（低优先） |

## 团队约定（示例，请按实际修改）

- 支付、退款、订单状态变更：默认不低于 P1
- 涉及幂等、重复回调、重复扣款：默认 P0
- 纯 UI 文案：默认 P3
