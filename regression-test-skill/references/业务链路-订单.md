# 订单业务链路（回归补全用）

## 主链路

```
浏览商品 → 加购 → 下单 → 创建订单（待支付）
       → 支付入口 → 支付成功 → 已支付 → 履约/发货
       → 取消（待支付）→ 已取消 → 库存释放 → 优惠券返还
```

## 取消相关链路

```
待支付 → 用户主动取消 → 订单状态：已取消
      → 库存预占释放
      → 优惠券锁定解除 / 返还
      → 支付入口关闭（不可再支付）
      → 购物车状态（若从购物车下单）
```

## 异常场景

```
重复取消 → 幂等：第二次取消应友好提示
取消后仍可调起支付 → P0 资金风险
取消后库存未释放 → P1 超卖风险
取消后优惠券未返还 → P1 用户体验与资损
```

## 回归补全结论

订单取消逻辑改动后，不能只测「取消按钮」；还应回归：

- 取消后订单状态流转
- 取消后支付入口是否失效
- 库存释放与重复取消幂等
- 优惠券返还
- 与支付回调的交叉场景（支付中与取消并发）
