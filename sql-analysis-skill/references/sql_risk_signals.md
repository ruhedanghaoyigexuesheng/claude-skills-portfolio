# SQL 高危信号（Step 1 必读）

> 命中以下信号不代表一定有问题，但必须在 Step 1 列出并在后续步骤展开分析。

## 查询写法

- `select *` — 返回字段过多，增加 IO 与网络传输
- 无 where / where 字段无索引 — 大表全表扫描风险
- `like '%关键词%'` — 前缀通配导致索引失效
- 函数包裹索引字段：`date(create_time)`、`upper(name)` 等 — 索引失效
- 隐式类型转换 — 如字符串列与数字比较
- 深分页：`limit 100000, 20` — 需扫描并丢弃大量行
- `or` 条件组合 — 可能导致索引合并或全扫
- `in (...)` 列表过长 — 优化器可能放弃索引

## 写操作

- `update` / `delete` 无 where — 误操作 / 锁表风险
- 大事务批量 update — 长锁等待

## 联表与聚合

- 大表 join 大表且无过滤 — 笛卡尔积或超大中间结果
- join 字段无索引 — nested loop 成本极高
- `group by` 大表 — 临时表 / filesort
- 子查询返回大结果集 — 外层再过滤

## 排序与分页

- `order by` 字段不在索引中 — filesort
- `order by` + 深分页叠加 — 高风险组合
- `distinct` 大表 — 去重成本高
