# 核心表数据量说明

> 用于输入契约 `data_volume` 字段及 Step 4 慢查询判断。以下为仿真练习数据，实际项目请替换为真实量级。

| 表名 | 数据量 | 增长趋势 | 备注 |
|------|--------|----------|------|
| order_info | 500 万+ | 日增约 2 万 | 核心交易表，status 区分度低 |
| user_info | 800 万+ | 日增约 3 万 | 用户主表 |
| pay_record | 450 万+ | 与订单 1:1 左右 | 支付流水 |
| order_item | 1200 万+ | 一单多行 | 订单明细 |
| user_log | 2 亿+ | 日增约 50 万 | 行为日志，大表查询高风险 |

## 数据量与风险参考

| 数据量 | 无索引全扫 | 低区分度 where | 深分页 |
|--------|------------|----------------|--------|
| < 10 万 | 通常可接受 | 视 QPS | 视业务 |
| 10 万–100 万 | P2 风险 | P1 风险 | P1 风险 |
| 100 万–1000 万 | P1 风险 | P0/P1 风险 | P0/P1 风险 |
| > 1000 万 | P0/P1 风险 | P0 风险 | P0 风险 |

## 区分度参考（order_info.status）

| status 值 | 占比（仿真） | 区分度 |
|-----------|--------------|--------|
| 1（待支付/进行中） | ~35% | 低 |
| 2（已完成） | ~55% | 低 |
| 3（已取消） | ~10% | 低 |

> status 单独作为 where 条件时，即使命中索引也可能扫描百万级行。
