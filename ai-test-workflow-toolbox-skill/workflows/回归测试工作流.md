# 回归测试工作流

> 工具箱路径：`ai-test-workflow-toolbox-skill/workflows/回归测试工作流.md`
> 详细步骤见同目录 `regression_testing.md`（已从单课迁移，路径已更新）
> 执行前加载：`system/AI测试工作台总规则.md`、`assets/回归规则库.md`

## 适用场景

- 版本发布前、hotfix 后确定回归范围
- 「这次改动要回归哪些模块」

## 必须引用

| 文件 | 用途 |
|------|------|
| `references/regression-test/输入契约-回归.md` | Step 1 |
| `references/regression-test/module-impact-map.md` | Step 2 |
| `references/regression-test/业务链路-支付.md` 等 | Step 3 |
| `references/regression-test/history-bugs-*.md` | Step 4 **禁止跳过** |
| `references/regression-test/回归-风险规则.md` | Step 5 |
| `references/regression-test/P0-P3-风险定义.md` | 风险对齐 |
| `assets/回归规则库.md` | **必须加载** |
| `system/风险等级规则.md` | 统一 P0–P3 |
| `outputs/回归测试清单输出格式.md` | 输出模板 |

## 执行步骤（7 步）

```
改动输入 → 解析直接改动模块 → 识别上下游影响 → 业务链路补全
    → 关联历史 Bug → 标记风险等级 → 输出回归清单 → 人工复核
```

逐步细节见 [`workflows/regression_testing.md`](regression_testing.md)（路径已对齐 `references/regression-test/`，无需手工替换）。

## 输入

- 模板：`templates/release_change.md`
- 主案例：`examples/regression-test/sample_release_payment_callback.md`
- 练习：`examples/regression-test/sample_release_order_cancel.md`

## 输出

必须符合 `outputs/回归测试清单输出格式.md`，含表格、P0 标记、触发原因、历史 Bug 关联。

## 禁止

- 跳过历史 Bug、不标风险、只列模块不写场景
- 替测试人决定「可以不上线」
