# 联动工作流

> 当一个 Bug 需要多助手协同时使用。主场景：**支付成功订单未支付**。

## 适用场景

```
一个 Bug → 同时看日志、查 SQL、定回归范围、（可选）验证 Prompt 是否稳定
```

## 执行顺序（禁止跳步、禁止混在一个 Prompt 里）

| 顺序 | 助手 | 工作流 | 输入 |
|------|------|--------|------|
| 1 | Bug 分析 | `workflows/Bug分析工作流.md` | `templates/bug_input.yaml` |
| 2 | 日志排查 | `workflows/日志排查工作流.md` | `templates/log_input.yaml` + traceId=abc123 |
| 3 | SQL 分析 | `workflows/SQL分析工作流.md` | `templates/sql_input.yaml` |
| 4 | 回归测试 | `workflows/回归测试工作流.md` | `templates/release_change.md` |
| 5 | Prompt 测试（可选） | `workflows/Prompt测试工作流.md` | 验证 Bug 分析 Prompt 未退化 |

## 统一要求

- 每步输出独立文件，格式见对应 `outputs/`
- 风险等级统一 P0（本主场景），遵循 `system/风险等级规则.md`
- 每步文末附 `system/人工复核规则.md` checklist
- 上一步产出可作为下一步输入参考，但**不得跳过 workflow 步骤**

## 主场景素材

| 素材 | 位置 |
|------|------|
| Bug 输入 | `templates/bug_input.yaml` |
| 日志 traceId=abc123 | `examples/bug-analysis/sample-error.log`、`assets/sample_logs/payment_lock_timeout.log` |
| order_info + payment_record | `references/sql-analysis/table_ddl.md` |
| 支付回调改动 | `templates/release_change.md` |
| 完整联动输出样例 | `examples/联动案例-支付成功订单未支付.md` |

## 验收标准

联动案例包含 **Bug + 日志 + SQL + 回归** 四类输出 + 统一 P0 风险 + 人工复核勾选项。
