# 日志排查工作流

> 工具箱路径：`ai-test-workflow-toolbox-skill/workflows/日志排查工作流.md`
> 执行前加载：`system/AI测试工作台总规则.md`、`assets/日志规律库.md`

## 适用场景

- 用户提供原始日志、ELK 导出、traceId 报错
- Bug 描述含「超时」「异常」「failed」

## 必须引用

| 文件 | 用途 |
|------|------|
| `references/log-analysis/log_keyword_types.md` | Step 1 **必须** |
| `references/log-analysis/exception_type_map.md` | Step 2 **必须** |
| `references/log-analysis/service_call_chain.md` | Step 3 |
| `references/log-analysis/module_owner_map.md` | Step 4 |
| `references/log-analysis/log_pattern_history.md` | Step 5 **必须** |
| `assets/日志规律库.md` | **必须加载** |
| `outputs/日志排查输出格式.md` | 输出模板 |
| `outputs/missing_evidence_checklist.md` | 证据不足时 |

## 必填输入

见 `templates/log_input.yaml`：`raw_log`（必填），建议 `trace_id`、`occurred_at`、`environment`、`business_scene`。

## 执行步骤（7 步，禁止跳步）

| 步骤 | 名称 | 产出 |
|------|------|------|
| 1 | 提取日志关键词 | 级别、服务、异常词、traceId |
| 2 | 识别异常类型 | 网络/DB/MQ/缓存/权限/业务 |
| 3 | 调用链分析 | entry → 上下游 → 异常节点 |
| 4 | 模块定位 | 业务模块 + 建议关注服务/表 |
| 5 | 匹配历史规律 | `assets/日志规律库.md` |
| 6 | 输出排查建议 | 按输出格式 |
| 7 | 证据不足处理 | 缺失信息清单，禁止根因 |

## 输出

- 正常：`outputs/日志排查输出格式.md`
- 证据不足：`outputs/missing_evidence_checklist.md`

## 案例

- 样例日志：`assets/sample_logs/payment_lock_timeout.log`
- 完整报告：`examples/log-analysis/payment_lock_timeout_report.md`
- 更多日志：`assets/sample_logs/`（7 个场景）

## 禁止

- 无 traceId 时断言「就是 XX 服务 bug」
- timeout 与 duplicate key 混称为「系统异常」
