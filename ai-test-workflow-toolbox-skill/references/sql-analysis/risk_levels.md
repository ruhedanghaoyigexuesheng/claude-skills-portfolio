# SQL 性能风险等级定义（P0–P2）

> 测试输出是**风险识别与验证建议**，最终索引方案由 DBA/开发确认。

| 等级 | 典型 SQL 场景 | 接口影响 | 处理要求 |
|------|---------------|----------|----------|
| **P0** | 大表全扫 + 高 QPS；深分页 + 排序叠加导致接口超时；写操作无 where | 核心接口不可用或大面积超时 | 立即与开发/DBA 确认，阻断发布或热修复 |
| **P1** | 低区分度 where + order by filesort；大表 join 无先过滤；慢查询 >1s | 核心列表/详情慢，偶发超时 | 24h 内 explain 验证并排期优化 |
| **P2** | 小表或低 QPS 下的 select *；可接受的全扫；有绕行方案 | 部分用户偶发慢 | 常规排期优化 |

## 判定参考

### P0 信号

- 核心表（>100 万行）无有效 where 或 where 区分度极低
- 深分页（offset > 10000）+ order by 叠加
- 接口已出现超时或 P99 > 3s
- update/delete 无 where（数据安全）

### P1 信号

- 大表按低区分度字段过滤 + 排序
- join 两张大表且驱动表未先过滤
- 慢查询日志中 >1s 且 QPS > 10
- select * 返回大字段（TEXT/BLOB）列表

### P2 信号

- 数据量 < 10 万或 QPS 极低
- 已有合适索引，explain 显示 rows 可控
- 非核心接口、可缓存

## 场景速查

| 场景 | 典型等级 | 理由 |
|------|----------|------|
| 订单列表 status=1 + 深分页 | P0/P1 | 500 万表 + 低区分度 + 深分页 |
| user_log 按 date(create_time) 查 | P1 | 2 亿表 + 函数致索引失效 |
| 报表库离线统计（低 QPS） | P2 | 非在线核心链路 |
| UPDATE order_info SET status=2（无 where） | P0 | 数据安全 |

## 输出格式

```markdown
## 7. 性能风险

| 字段 | 内容 |
|------|------|
| 风险类型 | 慢查询 |
| 风险原因 | status 低区分度 + order by create_time + 深分页 limit 100000,20 |
| 影响范围 | GET /api/orders 订单列表 |
| 可能表现 | 接口 P99 超时、DB CPU 升高 |
| 验证方式 | EXPLAIN + 慢查询日志（>1s） |
| 风险等级 | P1 |
```
