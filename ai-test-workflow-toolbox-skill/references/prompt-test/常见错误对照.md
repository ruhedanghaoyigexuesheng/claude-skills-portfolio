# Prompt 测试常见错误对照

| 错误做法 | 正确做法 |
|----------|----------|
| 只测一次，觉得能用就上线 | 稳定性至少 3 次；各类型样本至少 1 次 |
| 只测正常输入 | 边界 + 错误 + 证据不足都要测 |
| 只看内容多不多 | 看核心字段、格式、风险是否稳定 |
| 不测多轮一致性 | 同一对话内先定规则再测任务 |
| 不测幻觉 | 专门准备「证据不足」样本 |
| 凭感觉评价 | 填结构化报告 + 问题清单 |
| 稳定性在同一对话连跑 3 次 | 每次新开对话 |
| v1 不通过直接改原文件 | 另存 v2，保留 v1 对比 |
| 替测试人决定「可以上线」 | 报告给出建议，人工确认结论 |

## 自检方向

| 场景 | 期望 |
|------|------|
| 稳定性 | 3 次都覆盖验证码频控、过期、Token |
| 边界 | 「做一个登录」→ 应追问登录方式/规则 |
| 错误 | 「有效期 -5 分钟」→ 应指出参数不合理 |
| 多轮 | 第二轮仍用表格 + 风险列 |
| 幻觉 | 无频控规则时不应编造「每分钟最多 3 次」 |

## 目标评估表门槛

评估表 6 项中 **2 项以上答不上来** → 先改 Prompt，不要开测。
