# 多轮一致性测试脚本

> 在同一对话内按顺序发送，用于 Step 6 多轮一致性测试。

## 第一轮 — 定义规则

```
支付功能必须重点覆盖幂等、库存回滚、优惠券状态。
后续所有用例必须按 Markdown 表格输出，含风险等级列。
列名：用例编号 | 模块 | 场景 | 前置条件 | 测试步骤 | 预期结果 | 风险等级
```

## 第二轮 — 触发任务

```
@prompts/待测Prompt-用例生成.md

需求：用户可使用微信/支付宝完成订单支付。

请生成支付测试用例。
```

## 检查项（第二轮输出后逐项核对）

- [ ] 是否仍然覆盖幂等
- [ ] 是否仍然覆盖库存回滚
- [ ] 是否仍然覆盖优惠券状态
- [ ] 是否仍然按 Markdown 表格 + 风险等级列输出
- [ ] 列名是否与第一轮定义一致

## 常见失败表现

- 第一轮说按表格输出，第二轮变成段落
- 第一轮定义 P0 风险，第二轮不再标风险等级
- 第一轮要求覆盖幂等，第二轮只写「支付成功/失败」

## Bug 分析 Prompt 多轮变体

### 第一轮

```
Bug 分析时不得在无日志的情况下给出确定根因。
所有推测必须标注「待验证假设」。
输出必须包含「还需补充的证据清单」。
```

### 第二轮

```
@examples/prompt-test/sample_bug_ticket.md

请按 Bug 分析 Prompt 输出完整报告。
```

检查：是否遵守「不断言根因」规则；是否列出证据清单。
