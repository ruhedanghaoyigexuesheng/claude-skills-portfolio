# 联动案例：支付成功订单未支付

> 主场景综合实战。按 `workflows/联动工作流.md` 顺序产出四类助手输出摘要。

## 场景输入

- Bug：`templates/bug_input.yaml`
- 日志：traceId=abc123，见 `examples/bug-analysis/sample-error.log`
- SQL：见 `templates/sql_input.yaml`
- 回归：`templates/release_change.md`（v2.3.1 支付回调优化）

---

## 1. Bug 分析助手输出摘要

| 字段 | 内容 |
|------|------|
| 问题现象 | 第三方支付成功；订单表 status 仍为待支付；用户端展示一致 |
| 影响模块 | 支付回调、订单状态、MQ、支付流水 |
| 可能原因 | MQ 消费失败；回调幂等问题；状态更新时序 |
| 推荐日志 | payment callback、order status update、mq consume |
| 推荐 SQL | order_info、payment_record 对账查询 |
| 关联历史 Bug | BUG-2024-088（高相似）、BUG-2023-041（中相似） |
| 回归范围 | 支付、订单、库存、优惠券、退款 |
| 风险等级 | **P0** — 支付态与订单态不一致，阻断履约 |

完整报告：`examples/bug-analysis/payment-order-mismatch-report.md`

---

## 2. 日志排查助手输出摘要

| 字段 | 内容 |
|------|------|
| 异常类型 | MQ 消费异常 / 业务状态更新失败 |
| 调用链 | gateway → payment-service → mq → order-service |
| 疑似模块 | order-service 状态更新、mq-consumer |
| 关键词 | update order failed、mq consume error |
| 历史规律 | 匹配「update order status failed」→ 状态机/回调重复 |
| 风险等级 | **P0** |

完整报告：`examples/log-analysis/payment_lock_timeout_report.md`

---

## 3. SQL 分析助手输出摘要

| 字段 | 内容 |
|------|------|
| 风险信号 | join 两张大表；status 低区分度 where |
| 索引建议 | 建议验证 (order_id, status) 组合索引（需 explain） |
| 慢查询 | 500 万+ 行 join 无先过滤风险 P1 |
| 验证方式 | explain + 慢查询日志 |
| 风险等级 | **P1**（排查 SQL，非直接根因） |

完整报告：`examples/sql-analysis/order_list_slow_report.md`

---

## 4. 回归测试助手输出摘要

| 模块 | 场景 | 风险 | 触发原因 |
|------|------|------|----------|
| 支付回调 | 重复回调幂等 | P0 | v2.3.1 改动回调逻辑 |
| 订单状态 | 支付成功→已支付 | P0 | 核心链路 |
| 库存/优惠券 | 扣减与回退 | P0 | 支付后链路 |
| 退款/对账 | 全链路 | P1 | 历史 Bug BUG-2023-041 |

完整清单：`examples/regression-test/sample_release_payment_callback.md`

---

## 统一风险等级

**P0** — 资金与订单状态不一致，核心交易链路阻断。

---

## 人工复核点

- [ ] 根因是否有日志/SQL/接口证据
- [ ] 风险等级是否与业务影响一致
- [ ] 回归范围是否过大或过小
- [ ] SQL 优化建议是否需研发/DBA 确认
- [ ] 日志证据是否完整（含 traceId 链路 abc123）
- [ ] 各助手结论模块定位是否一致
