# 风险等级定义（P0–P3）

| 等级 | 典型场景 | 处理要求 |
|------|----------|----------|
| **P0** | 重复扣款、资金不一致、大面积不可用 | 立即升级，阻断发布 |
| **P1** | 订单状态错误、核心流程受阻 | 24h 内修复验证 |
| **P2** | 部分用户、可绕行 | 排期修复 |
| **P3** | UI 文案、非核心展示 | 常规排期 |

## 判定参考

### P0 信号

- 涉及资金损失或重复扣款
- 核心交易链路完全不可用
- 大面积用户受影响（>10% 或关键客户）
- 数据不一致且无法自动修复

### P1 信号

- 核心流程受阻但可绕行
- 订单/支付状态错误（如「支付成功订单未支付」）
- 关键功能异常，影响用户体验

### P2 信号

- 部分用户偶发
- 非核心功能异常
- 有临时 workaround

### P3 信号

- UI 展示问题
- 文案错误
- 非核心模块、低流量场景

## 场景速查

| 场景 | 典型等级 | 理由 |
|------|----------|------|
| 支付成功订单未支付 | P0/P1 | 资金链路 + 用户无法完成交易 |
| 库存超卖 | P0 | 资损风险 |
| 登录 Token 失效 | P1 | 核心流程受阻 |
| 接口超时 | P1/P2 | 视影响范围而定 |
| 按钮文案错误 | P3 | 非核心展示 |

## 输出格式

```markdown
## 风险等级

**等级**：P1

**理由**：支付成功但订单状态未更新，属于核心交易链路状态不一致，用户无法完成交易，需 24h 内修复验证。
```
